# OpenSpec Explore

## 触发方式
用户输入 `/opsx:explore` 或表示需要探索、讨论、理清思路时触发。

## 工作流程

### 1. 理解探索意图
- 用户想要探索什么问题？
- 是技术可行性、架构方案、还是需求澄清？
- 是否有已有的 proposal 或 design 需要深入？

### 2. 探索模式行为

在探索模式中，Claude 应该：

**主动提问**
- 挖掘隐含需求
- 识别潜在冲突和边界
- 确认优先级和约束

**分析现状**
- 阅读相关代码，理解当前实现
- 查找相关的 specs 文档
- 识别技术债务和限制

**提供选项**
- 给出多个可行方案
- 分析各方案的优劣
- 推荐最佳方案并说明理由

**可视化思路**
- 用简单的文字图描述架构
- 列出关键决策点
- 整理依赖关系

### 3. 探索产出

探索结束后，根据讨论结果：
- 如果思路清晰 → 建议用户执行 `/opsx:propose` 生成正式规格
- 如果需要进一步验证 → 列出待验证事项
- 如果发现阻塞 → 明确标记阻塞点和解决路径

### 4. 探索记录（可选）

如果探索过程产生了有价值的结论，可在 `specs/proposals/` 中创建草稿：

```
specs/proposals/{date}-{slug}-draft.md
```

标记为 `[DRAFT]`，待后续 propose 时正式化。

## 探索原则
- 不急于给出最终方案，重在理清问题
- 鼓励用户表达想法，而不是直接指定方案
- 保持开放性，允许方向调整
- 记录关键决策和理由
