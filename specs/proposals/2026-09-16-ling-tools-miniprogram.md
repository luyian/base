# 提案：元灵工具箱微信小程序

## 背景

用户需要一个全新的、与现有「简基」小程序独立的小程序「**元灵工具箱**」，提供「文件转换」与「打卡」两大常用工具。视觉适配现有小程序的 front-end-design（中式印章美学），登录与后端完全复用现有 base 体系，不新增后端代码。

## 目标

1. 新建独立小程序工程 `ling-tools/`，与 `minservice/` 平行，互不影响。
2. 提供 tabBar：首页（工具箱入口）/ 文件转换 / 打卡 / 我的。
3. 文件转换小程序端可用：PDF 转 Word、转 Markdown、压缩（含滑动条档位 + 预计大小），复用现有后端接口与 python-tools 链路。
4. 打卡整体迁移现有功能与中式设计。
5. 登录复用现有 auth（账号密码 / 微信一键登录 / 绑定），主题复用 light/dark 体系。

## 非目标

- 不新增任何后端接口或数据库表。
- 小程序「文件转换」首页仅做一个宫格入口；页面内用三 tab 切换（压缩/整理/转换），不做独立多宫格。
- 不做小程序自有支付/订阅等能力。

## 关键决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 代码位置 | 新建 `ling-tools/` 独立目录 | 用户确认，不动现有简基 |
| 后端 | 完全复用现有接口 | 用户确认，后端零新增 |
| tabBar | 首页/转换/打卡/我的 四项 | 用户确认「首页入口 + 我的」 |
| 文件转换后端 | 直接调现有 `/system/file-convert/*` + `/system/scan-doc/*` | 用户确认 |
| 文件转换入口 | 首页单宫格「文件转换」→ 页内三 tab（压缩/整理/转换） | 用户确认：单页面内 tab 切换 |
| 压缩能力 | PDF 压缩（滑块 40~250 dpi + 预计大小 + 低于极致 tips） | 复用 Web |
| 整理能力 | **完整扫描整理工作区**（建区/多图追加/排序/删/完成合 PDF） | 用户确认做完整版 |
| 转换能力 | PDF→Word、PDF→Markdown | 复用 Web |
| 上传 | `wx.uploadFile`（小程序标准能力） | 小程序不支持浏览器 FormData |
| 下载/预览 | `wx.downloadFile` + `openDocument` / `saveFile` | 替代 Web 的 `window.open` |
| 打卡 | 整体迁移 `minservice/pages/checkin` 全套 | 功能成熟，直接复用 |
| 登录/主题/request/nav-bar | 迁移复用 | 保持一致体验 |
| 视觉 | front-end-design 中式（paper/ink/seal 变量体系） | 与打卡一致，用户指定 |

## 风险

- 小程序 `wx.uploadFile` 对超大文件（近 50MB）上传耗时与中断 → 前端提示、增加 loading；如需可后续加分片。
- 微信小程序需在公众平台配置服务器域名（合法域名校验 `urlCheck`）。开发期可临时关。
- appid 需用户注册「元灵工具箱」后提供。
- COS 下载 URL 需为 https 且在后台配置白名单，否则 downloadFile 失败。
