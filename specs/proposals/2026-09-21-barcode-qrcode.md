# 提案：通用条码/二维码能力层 + 商品管理场景

## 背景

用户需要一套**通用的条码/二维码能力**：既能**生成**条形码/二维码子图，也能**识别**图片中已有的条码/二维码内容。能力必须**与业务解耦**，底层只处理"内容字符串 ↔ 条码图"，不关心内容含义；未来可服务于任何业务，而**商品管理**是第一个落地的业务场景。

商品场景核心流程：**PC 端生成条形码 → 条码贴到商品上 → 小程序端扫码（`wx.scanCode`）→ 找到对应商品并编辑信息 → 保存**；若扫到的码未对应商品，则新建一个商品并绑定该码。

**端职责分工（用户确认）**：PC 端**不做扫码**，仅负责**商品数据管理**与**生成条码/二维码**（供下载/打印贴标）；**小程序端不生成码**，仅负责**扫码命中商品 + 编辑表单保存**，被扫的码是 PC 端已生成的贴标码（或商品自带码）。

条码采用**间接编码**（条码内容是业务唯一编码字符串，编码映射数据库记录 ID），扫码命中编码后找到对应记录。

工具在 **PC 端管理后台**与 **小程序** 双端使用，数据统一存入后端数据库，按用户维度隔离。

## 目标

1. **通用编解码 API**（彻底解耦，不耦合任何业务表）：
   - `POST /barcode/generate`：给定内容 + 码制（条形码/QR）→ 返回条码 PNG。
   - `POST /barcode/decode-image`（python-tools）：上传图片 → 返回识别出的条码/二维码**原始内容字符串**（是否命中业务由调用方决定）。
   - `POST /barcode/code-record`：给定内容 + bizType + bizId 登记一条通用条码记录（不校验业务表是否存在）。
2. **通用条码记录表** `t_barcode`：含 `biz_type` + `biz_id`，可与任意业务对象关联；商品只是 `biz_type=PRODUCT` 的一种。
3. **商品管理**：商品表 + 关联条码 + 价库字段 + 来源区分；含扫码编辑保存全流程。
4. 双端界面化，商品数据按用户隔离，登录/权限复用现有体系。

## 非目标

- 不做批量印刷/打印布局引擎（条码图由生成 API 输出，前端渲染展示/导出）。
- 不做进销存的出入库/订单能力（仅商品主数据 + 价库字段 + 关联条码）。
- 不做商品图 OCR 商品名识别（仅识别图片中的条码/二维码内容）。
- 不新增第三方扫码 SDK：小程序用 `wx.scanCode`，图片识别走 python-tools 解码。

## 关键决策（已确认）

| 决策点 | 选择 | 说明 |
|---|---|---|
| 能力分层 | 通用层（编解码 + 通用条码记录）与业务层（商品）分离 | 用户确认：用到别处、彻底解耦 |
| 编解码 API | 后端 generate + python-tools decode-image，均不耦合业务表 | 用户确认 |
| 通用条码记录表 | `t_barcode`（biz_type + biz_id 可关联任意业务） | 用户确认 |
| 识别返回 | python-tools 仅返回识别到的**原始内容字符串**，不决定命中逻辑 | 用户确认 |
| 商品命名域 | `product`，`com.base/product`，表 `t_product` | 条码记录复用 `t_barcode` |
| 条码内容形式 | 业务唯一编码字符串；商品场景编码与商品 1:1 | 通用记录可一 type 多条 |
| 商品信息字段 | 名称、分类、规格、单位、**售价、成本、库存、供应商、生产日期**、备注 | 用户确认含价库 |
| PC 端职责 | **不做扫码，仅数据管理 + 生成条码/二维码供下载/打印贴标** | 用户确认 |
| 扫码载体 | 仅小程序端 `wx.scanCode` 扫真实条码命中商品 | 用户确认 |
| 小程序职责 | **不生成码**，仅扫码 + 编辑表单保存 | 用户确认 |
| PC 端职责 | 生成条码/二维码 + 数据管理 | 用户确认 |
| 生成码 | 可生成条形码(CODE128)与二维码(QR)两种子图 | 用户确认 |
| 条码来源区分 | `t_barcode.source`（1 自生成 2 图片识别录入） | 来源字段保留（本期小程序仅扫码，自生成为主） |
| 双端接口 | 后端一套 REST，PC/小程序共用 | 规划阶段定权限码 |
| 打印/导出 | 生成 API 输出条码 PNG，PC 导出/下载 | 小程序本期不生成码 |

## 风险

- 小程序 `wx.scanCode` 扫读真实条码为唯一入口，流程单一清晰。
- PC 端不做扫码：商品编码依赖后端自动生成（`/prod/generate-code`），PC 生成条码贴标。
- 后端 `decode-image` 通用识别接口保留（可复用于未来其它业务），本期小程序 UI 不接入。
- 并发生成唯一编码 → 用数据库唯一索引 + 应用中生成兜底。
- 通用表 `t_barcode` 不设业务外键，一致性由业务层自行保证（符合阿里巴巴禁外键规范）。
