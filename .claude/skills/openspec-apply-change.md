# OpenSpec Apply Change

## 触发方式
用户输入 `/opsx:apply` 时触发。

## 前置条件
- `specs/tasks/` 目录下存在对应的任务文件
- 任务文件中有未完成的任务项（`- [ ]`）

## 工作流程

### 1. 加载任务清单
- 扫描 `specs/tasks/` 目录，列出可用的任务文件
- 如果有多个任务文件，让用户选择
- 读取任务文件，展示当前进度

### 2. 选择下一个任务
- 找到第一个未完成的任务（`- [ ]`）
- 展示任务描述和相关上下文
- 确认用户要执行该任务

### 3. 执行任务
按照以下步骤实现：

**a. 阅读规格**
- 读取对应的 `specs/specs/` 文件
- 读取对应的 `specs/designs/` 文件
- 理解要实现的具体规范

**b. 阅读现有代码**
- 查找相关的现有代码
- 理解当前的代码结构和模式
- 确认修改点

**c. 实现变更**
- 按照规格文档编写代码
- 遵循项目的编码规范（阿里巴巴规范）
- 匹配现有代码风格

**d. 验证**
- 运行相关测试
- 检查编译是否通过
- 确认功能符合规格

### 4. 更新任务状态
任务完成后，更新任务文件：
```markdown
- [x] 任务描述  ← 标记为完成
```

### 5. 记录变更
按照 CLAUDE.md 的要求，将修改内容记录到 `.claude/docs/TEMP.md`

### 6. 暂存文件
将新增/修改的文件添加到 git 暂存区（不 commit）

## 执行原则
- 每次只执行一个任务
- 严格按照 specs 中的规格实现，不自行发挥
- 如果发现规格有问题，暂停并告知用户
- 保持增量推进，每个任务都是可验证的小步骤
