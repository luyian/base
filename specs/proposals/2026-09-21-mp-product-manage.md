# 提案：小程序端商品管理页（改建现有条码扫码页）

## 背景

当前小程序 `pages/barcode/barcode` 已实现「扫码 → 命中编辑 / 未命中新建绑定」，但**没有商品列表管理**：不能浏览已有商品、手工添加/编辑商品、为某商品绑定码。PC 端已有完整商品管理后台，小程序端需补齐商品管理能力，形成统一入口。后端商品/条码接口已齐全，本期**零后端改动**，纯小程序前端改造。

用户确认：**其他功能（PDF/去水印/打卡等）一律不动**，只做商品管理。

## 目标

将小程序 `pages/barcode/barcode` **改建为商品管理页**，实现：

1. **商品列表管理**：展示我的商品（分页加载），列表项显示商品名称 / 编码 / 分类 / 库存；提供「添加商品」「编辑」「扫描绑定」「删除」操作。
2. **添加 / 编辑商品**：表单新增（不扫码也可手工添加）、编辑已有商品（含扫码命中的编辑）。
3. **扫码编辑商品**：扫已绑定条码 → 命中商品 → 进入编辑。
4. **扫码绑定商品**：扫到未绑定/未知条码 → 绑定到指定商品（或新建商品并绑定）。

## 非目标

- 不在小程序生成条码/二维码（沿用 PC 端生成、小程序仅扫码的职责划分）。
- 不展示商品条码图片（小程序端不打印/不预览图片，本期不接入，避免 COS 预签名图片在小程序加载的不必要复杂度）——如后续需要可再补 `listProductCodes` 图片列。
- 不做进销存、出入库。

## 页面结构（`pages/barcode/barcode.*` 改建）

```text
商品管理页
├─ 顶栏 nav-bar「商品管理」
├─ 主操作区（保留扫码大按钮）
│   ├─ 扫码：命中→编辑该商品；未命中→弹「新建并绑定 / 取消」
│   └─ 添加商品按钮（手工新增表单）
├─ 商品列表（分页）
│   └─ 每行卡片：名称 / 编码 / 分类 / 库存
│       ├─ 「编辑」→ 编辑表单
│       ├─ 「扫码绑定」→ 为该商品绑定一个未绑定码
│       └─ 「删除」→ 确认后删除（逻辑删除）
├─ 编辑/新增表单（复用现有 form 字段与样式）
│   └─ 底部「保存」；命中商品场景顶部回显当前扫码 code 徽标
└─ 扫码绑定商品选择（命中未绑定/未知码时）
    └─ 选择绑定到哪件商品（本页列表）→ confirm
```

## 关键交互

| 场景 | 行为 |
|---|---|
| 顶部「扫码」（编辑）：扫到已绑定商品码 | 命中 → 弹编辑表单（顶部 code 徽章，保存走 `PUT /prod/{id}`） |
| 顶部「扫码」扫到未绑定/未知码 | `scanProduct` 返回 null → toast 提示「未命中商品」，引导用列表行「扫码绑定」 |
| 点「添加商品」 | 空白表单，保存走 `POST /prod`（系统自动生成商品编码 PROD） |
| 点商品行「编辑」 | 预填该商品，保存走 `PUT /prod/{id}` |
| 点商品行「扫码绑定」 | **先确定商品** → `wx.scanCode` → 扫到内容后 `POST /prod/{id}/bind`（type 按码制区分） |
| 点商品行「删除」 | `wx.showModal` 确认 → `DELETE /prod/{id}` |

> 绑定顺序经用户确认为「**先选商品再扫码**」：在商品列表某针对应行点「扫码绑定」，再扫张贴的码。顶部大「扫码」仅用于命中后编辑商品。

## 复用的后端接口（已存在，无改动）

`GET /prod/list`、`POST /prod`、`PUT /prod/{id}`、`DELETE /prod/{id}`、`GET /prod/scan/{code}`、`POST /prod/{id}/bind`、`GET /prod/codes/{id}`。

## 改动文件

- `ling-tools/app.json`：页面注册不变（沿用 `pages/barcode/barcode`，仅内容改建）；首页入口文案「条码/二维码」→「商品管理」（可选，或保持）。
- `ling-tools/pages/index/index.js|.wxml|.wxss`：入口名与图标语义对应商品管理（小改）。
- `ling-tools/pages/barcode/barcode.js|.wxml|.wxss`：改建为主列表 + 表单 + 扫码三大区块（核心改动）。
- 后端、`api/product.js`、`utils/request.js` **不变**。

## 风险

- 列表分页下拉/加载更多交互，微信原生需用 `onReachBottom`。
- 「扫码绑定」需在扫到未绑定码后承载「选择商品」UI；用 `wx.showActionSheet` 或页面内弹层实现。
- 主题（深/浅色）沿用现有 Design Token，新列表/表单样式保持 `--paper/--card/--ink/--seal` 体系。
